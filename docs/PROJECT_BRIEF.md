# EDM Lab 홈페이지 재구축 — 프로젝트 브리프

> 작성: 2026-11-14 / 이 문서는 "목표와 큰 틀"이다. 세부 구현은 너(Claude Code)의 전문적 판단에 맡긴다.
> 더 나은 레이아웃·구조·도구가 보이면 **근거와 함께 제안**하라. 단, `[고정]` 항목을 바꾸려면 사용자 승인이 필요하다.

---

## 1. 목적과 대상
- **연구실**: EDM Lab (Environmental Durability Metals Laboratory, 환경내구금속연구실)
- **책임교수**: 김혜진, 한국공학대학교 신소재공학과 조교수 (2025.3~)
- **주요 대상**
  1. **신규 학생**(학부연구생·대학원 진학 희망자) — 학과 설명회 등 연 1~2회 집중 유입. "이 연구실에서 무엇을 배우고, 어떻게 지원하는가"가 빨리 보여야 한다.
  2. **협업 대상**(타 대학 교수, 기업·연구소) — 연구 역량과 실적을 신뢰감 있게 확인할 수 있어야 한다. 교수 산업계 경력(현대제철 연구소 약 10년), 대표 논문, 연구 분야가 핵심.
- **운영 방식**: 1~3개월 간격 비정기 업데이트. 사용자가 자료를 주면 CC가 데이터 파일만 수정하고 push한다.

## 2. 디자인 방향
- **색상/느낌**: 친환경적이고 밝은 느낌의 **파란색 계열**. 예: 맑은 블루를 주색으로, 청록·그린 계열을 보조색으로, 밝은 배경.
  - Step 2에서 **2~3개 팔레트 시안**을 만들어 사용자가 고르게 한다. 텍스트 대비는 WCAG AA 이상.
- 대학 연구실 홈페이지의 일반적인 신뢰감 있는 톤. 과한 애니메이션은 쓰지 않는다.
- 참고 예시(복제 대상 아님): https://mamel.snu.ac.kr/ — 랜딩 1장 + 서브 페이지, 연구 주제 카드형 구성
- PC·모바일 모두 각 화면에 맞게 동작해야 한다(모바일 우선 반응형).

## 3. 주소 구조
- `[고정]` GitHub 소유자: `edm-lab` (기존 사이트 https://edm-lab.github.io/MSE/ 의 소유자)
- **1순위**: 새 저장소 `edm-lab/edm-lab.github.io` 생성 → 루트 주소 `https://edm-lab.github.io/`
  - 주소는 로그인 이메일이 아니라 **소유자 이름(edm-lab)**으로 결정된다. edm-lab이 개인 계정이든 organization이든 `edm-lab.github.io` 저장소를 만들 수 있다. Step 0에서 실제 가능 여부를 확인할 것.
  - 기존 `edm-lab/MSE`는 개발 기간 동안 **그대로 둔다**(구 사이트 계속 운영). 정식 오픈 단계에서 새 주소로 안내/리디렉트하는 페이지로 교체한다.
- **2순위(루트가 불가능할 때만)**: 짧은 이름의 프로젝트 저장소(예: `edm-lab/lab` → `/lab/`). Step 0에서 대안과 함께 보고.
- 페이지 경로(기본안, 개선 제안 가능):
  ```

  /members/             구성원·졸업생
  /teaching/            강의
  /facilities/          장비·시설
  /news/                소식
  /join/                학생 모집
  /contact/             연락처·오시는 길
  (향후) /en/...        영어 버전. 지금은 만들지 않되 확장 가능한 구조로
  ```
  끝에 `/`를 붙이는 경로를 쓴다(`permalink: pretty`).

## 4. 기술 원칙
`[고정]` 원칙 — 바꾸려면 승인 필요
- **GitHub Pages 기본 빌드로 동작**할 것. push만으로 배포가 끝나야 한다. GitHub Actions·npm 빌드 체인은 쓰지 않는다.
- **콘텐츠와 디자인 분리**: 업데이트되는 모든 콘텐츠는 데이터 파일(YAML 등)에 둔다. 콘텐츠 업데이트 때 템플릿과 CSS를 고치지 않는다.
- 외부 의존성 최소화: CSS·JS 프레임워크와 외부 테마 gem을 쓰지 않는다. 의존성이 노후화되면 유지보수 부담이 생긴다.
- 한국어를 기본으로 하고, 필요할 때만 영어를 병기한다. 향후 영어판으로 확장할 수 있도록 UI 문자열은 분리해 둔다.
- 개발 기간에는 `noindex`를 켜 둔다.

`[기본안]` — 더 나은 방법이 있으면 제안
- Jekyll(GitHub Pages 내장) + `_data/*.yml` + `_layouts`/`_includes` 직접 작성
- 순수 CSS 1~2개 파일. 색·폰트는 `:root` CSS 변수로 한곳에서 정의
- 바닐라 JS 최소한(모바일 메뉴 정도)
- 폰트: Pretendard + 시스템 폰트 fallback
- 플러그인: `jekyll-seo-tag`, `jekyll-sitemap`
- 로컬 검증: `github-pages` gem(GitHub와 같은 버전)
- 이미지: WebP, 긴 변 1600px / 인물 600px. 변환 스크립트 1개를 로컬 전용으로 둔다(`scripts/`).
- 사진이 없어도 레이아웃이 어색하지 않아야 한다. 사진이 없으면 디자인된 placeholder나 사진 없는 레이아웃으로 자연스럽게 대체한다. (2026-11-14 추가)

### 자료 수신 방식 (2026-11-14 확정)
- 사용자 제공 자료(이미지, 엑셀, PDF, 텍스트)는 `_inbox/`로 들어온다. 하위 폴더(`profile/`, `research/`, `members/`, `facilities/`, `news/`, `logo/` 등)는 선택 사항이다.
- CC는 처리 전에 "파일 | 판단한 용도 | 저장 경로 | 연결할 데이터 항목 | 비고" 표를 보여주고 확인을 받는다. 용도가 불명확하면 질문한다.
- 확인 후 최적화 스크립트로 변환해 `assets/images/<분류>/`에 저장하고 데이터 파일에 연결한다. 처리한 원본은 `_inbox/_done/YYYY-MM-DD/`로 옮긴다.
- `_inbox/`는 git에 올리지 않는다(`.gitignore`). Jekyll도 `_`로 시작하는 폴더라 빌드에서 자동 제외한다.

## 5. 콘텐츠 구성 (기본안)
| 데이터 | 용도 | 비고 |
|---|---|---|
| site | 연구실명, 연락처, 외부 링크, 학생 모집 on/off·문구 | |
| ui | 메뉴·버튼 등 UI 문자열 | 영어 확장 대비 |
| profile | 교수 CV(학력, 경력, 학회활동, 수상, 링크) | |
| research | 연구 분야(카드 요약 + 상세 + 이미지) | |
| publications | 국제/국내 논문, 학회발표, 특허 | 대표 논문 `featured` 표시, 교수 이름 자동 강조 |
| projects | 수행 과제·협력 기관 | **협업 대상용으로 신규 제안**. 사용자 자료가 오기 전까지 비워 둔다 |
| members | 재학생·졸업생 | 졸업 시 삭제하지 않고 alumni로 전환 |
| courses | 강의 | |
| equipment | 장비·시설 | |
| news | 소식 | 메인에 최신 N건 자동 노출 |

- 위 구성은 출발점이다. 필드 설계와 파일 분할은 네가 최적화해도 된다. 확정한 스키마는 각 파일 상단 주석과 CLAUDE.md에 기록한다.
- 랜딩 페이지에서는 두 독자층(학생 / 협업자)이 각자 원하는 곳으로 빠르게 갈 수 있어야 한다. 구성 방식은 네가 제안한다.

## 7. 단계 계획
각 Step은 **한 세션 안에 끝낼 수 있는 크기**로 나눴다. Step이 끝날 때마다 커밋하고, `docs/PROGRESS.md`를 갱신하고, 보고한 뒤 **멈춘다.** 다음 Step은 사용자가 승인하면 시작한다.
Step 구성과 순서도 더 나은 방법이 있으면 제안해도 된다.

| Step | 내용 | 완료 기준 |
|---|---|---|
| 0 | 환경·계정 확인, 구 사이트 분석, **개선 제안** | 보고서만 작성(변경 없음) |
| 1 | 새 저장소 생성, Jekyll 골격, Pages 활성화, `PROGRESS.md` 생성 | 새 URL에 빈 골격 페이지 표시, 경로 구조 동작 |
| 1.5 | 자료 수신 방식(`_inbox/`) 확정 | 완료(2026-11-14) |
| 2 | 디자인 시안: 팔레트 2~3안, 랜딩 + 서브 1페이지(`/professor/`) 레이아웃, 사진 없는 상태, 로고 비교, 폰트 로딩 비교 | PC·모바일 스크린샷 → **사용자 선택** |
| 3a | 데이터 스키마 확정 + 논문·발표 이관(DOI 조회) | 빌드 통과, 매칭 결과 표·TODO 목록 보고 |
| 3b | 교수·연구·강의·연락처·소식 텍스트 이관 + `_inbox/` 자료 처리 | 빌드 통과, 이관/TODO 목록 보고 |
| 4 | 전체 페이지 구현 | 모든 경로 동작, 스크린샷 보고 |
| 5 | 품질 점검(반응형, 링크, 이미지 용량, 접근성, Lighthouse 등) + CLAUDE.md 운영 절차 최종화 | 점검 결과 보고 |
| 6 | 정식 오픈: noindex 해제, 구 MSE 사이트를 안내/리디렉트 페이지로 교체 | **사용자 승인 후에만** 실행 |
